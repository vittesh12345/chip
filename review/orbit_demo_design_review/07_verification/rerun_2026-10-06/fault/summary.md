# ORBIT-AI demonstrator: fault injection (area `fault`)

Generated by `make fault` on 2026-10-06. Overall result of the checks: **PASS**.

What this shows: which single-event upsets (SEU) the duplicated lane storage and the
triplicated thermal state catch, what escapes from the unprotected flip-flops, and how
often, measured on the production RTL. Faults are injected only into generated copies of
the RTL (formal) or from the testbench by hierarchical assignment (simulation); the
production RTL in `rtl/` is read, never modified, and has no fault ports.

## Part A: formal fault injection on generated copies (SymbiYosys)

`fault/gen_fault_copies.py` reads the RTL and writes one copy per scenario to
`$(BUILD)/fault/formal/<scenario>/`: every module renamed `*_fi`, and exactly one storage
element of the lane (or thermal) module made upsettable. For an `orbit_keep_reg` instance the
copy switches that one instance name to `orbit_keep_reg_seu_fi`, a variant whose
sequential block is split into the unchanged next-state logic and a register
`q <= q_next ^ fi_mask`, with `fi_mask` one bit (`fi_bit = $anyconst`) in one solver-chosen
cycle (`fi_req = $anyseq`). The copy keeps the production port list (checked by the
generator). Each diff is in `injection/<scenario>.diff`.

Harness `fault/fi_harness.sv`: the production `orbit_demo` (fault-free reference) and the
copy run in lockstep on the same unconstrained inputs (reset in cycle 0 only; reset,
`clear_fault`, temperature, handshakes free afterwards). Fault model: at most one upset per
trace in the whole design, in any cycle including reset cycles, any lane, any bit. An upset
requested in cycle k is stored at the edge ending cycle k and is visible from cycle k+1
(the *upset-visible cycle*), which is what a flip at the falling edge does in simulation.
In this synchronous model a flip anywhere inside a clock period acts at the next edge like a
flip at the start of that period (timing closure assumed; a flip inside the setup / hold window,
i.e. metastability, is out of scope), so the model covers every flip time.

Depth: every protected scenario is an **unbounded** proof (k-induction with k = 4; the base
case is BMC over 4 steps and the induction step closes), so it holds for traces of any length,
not only the 8 steps of the brief. Not part of the flow, tried once by hand during development
on `acc_a`: a BMC of the port-level properties *without* the helper invariants did not get far
(after about 10 minutes yices was at step 8 and abc bmc3 at frame 10, each step slower than the
last, because the solver re-derives the equality of the two multiplier / adder datapaths in
every unrolled step); a 24-step BMC *with* them passed in 7 minutes, which the unbounded proof
already implies.

### What is proven (accumulator and result scenarios, `L_*` and `D_*`)

For an upset in one copy of accumulator or result storage (any lane, bit, cycle):

* `L_lockstep_before_upset`: until the upset, all 521 state bits of the copy equal the reference.
* `L_single_bit_in_target`: in the upset-visible cycle exactly one state bit differs, inside the target element.
* `L_stop_in_upset_cycle`: in that same cycle `mismatch` is 1 and `in_ready` = `out_valid` = 0.
* `L_fault_next_cycle`: `fault` is 1 in the next cycle, unless reset or `clear_fault` is asserted
  in the upset-visible cycle; `L_overwritten_no_fault`: in that case (the only way the upset copy
  can be overwritten before it is used, since `in_ready` is already 0 so no beat or result can
  write it) there is no fault and all 521 state bits equal the reference again one cycle later.
* `L_fault_sticky`: `fault` stays 1 until reset / `clear_fault`; `L_resync_after_clear`: after any
  reset / `clear_fault` the copy equals the reference bit for bit (recovery).
* `L_stop_blocks`, `L_stop_only_after_upset`: a stop blocks both handshakes and never happens
  without an upset (no false alarm); `L_thermal_unaffected`: voted state, admission, repair flag
  and shutdown request equal the reference in every cycle.
* `D_out_fire_matches_ref`: **every `out_fire` of the upset copy is an `out_fire` of the reference
  in the same cycle with identical `out_data`** (no wrong, extra or duplicated result, ever);
  `D_no_wrong_result`, `D_no_extra_result`: the same for presented results; `D_no_silent_loss`:
  a result the reference presents is withheld only while the copy is stopped (`fault` or
  `mismatch`); `D_no_silent_beat_divergence`: `in_ready` differs from the reference only while stopped.

### What is proven (thermal scenarios, `T_*` and `D_*`)

For an upset in one thermal copy (either bit, any cycle): `T_voted_state_equal` and
`T_admission_equal` (voted state, `admit` and `in_ready` equal the reference in every cycle),
`T_other_ports_equal` (`out_valid`, `out_data`, `fault`, `shutdown_req` too; no fault stop),
`T_copy_rewritten_next_cycle` (one cycle after the upset-visible cycle the upset copy equals
the other two and the reference), `T_repair_iff_disagree` (`therm_repair` is high exactly while
the three copies do not all agree), `T_repair_only_upset_cycle` (which is exactly the
upset-visible cycle), `T_repaired_after_upset` (from then on all 521 bits equal the reference),
plus `T_lockstep_before_upset`, `T_single_bit_in_target` and the `D_*` checks.

`H_*` are helper invariants for the induction (the reference's copies agree and its `fault_q`
is 0; after the upset the copy is either back in lockstep or stopped with a latched fault). They
are asserted and proven like the others, not assumed. The cover tasks show that the upset is
reachable at the lowest and highest bit of the target, while a result is being transferred /
a beat accepted, in NORMAL, THROTTLE and STOP, with the upset copy reading the unused code 3,
in the `clear_fault`-overwrite case, and that results flow again after fault and `clear_fault`.

## Part B: simulation SEU campaign (Icarus Verilog)

`fault/tb_seu_campaign.v`: two copies of the production design, each behind its own host
(driver, scoreboard written from SPEC sections 3-5, fault reaction = `clear_fault` two cycles
after `fault` is seen). Both get the same random workload (beats with random `in_first` /
`in_last`, random and edge-case operands, 85 % beat offers, 75 % `out_ready`, a temperature
profile of random segments through NORMAL, the hysteresis band, THROTTLE, STOP, invalid
sensor and cold; 1 trial in 8 also has rare scheduled `clear_fault` pulses). Per trial: reset,
a random prefix (8..127 cycles, stratified per bit), one bit of one copy flipped by
hierarchical assignment at the falling clock edge, 64 more cycles, then a drain (cool, consumer
ready; 24 cycles with beats, 8 without). The bench checks that the two copies are identical
before the flip and differ in exactly the intended bit after it. Outcomes: MASKED (port trace
identical to the fault-free copy), DETECTED (`fault` rose, no wrong data transferred),
REPAIRED (only `therm_repair` differed), TIMING (no fault, every result correct, but the port
trace differs, e.g. a shifted throttled admission), SDC (a transferred result is wrong), LOST
(an accepted result dropped without fault), EXTRA (a result transferred with none pending:
duplicate or stale), HANG (no beat accepted in the drain, even after the host's `clear_fault`), OTHER.

## Limits of these results

* Single-upset model: one flipped bit per trace / trial. Multiple-bit upsets, an upset in both
  copies of a pair (common mode) and upsets in combinational logic other than the shared product
  (comparators, voter, handshake logic, clock, reset) are not injected. The product scenario
  stands for the whole class of common-mode datapath faults: they are not detected.
* The formal reference is the production RTL itself. Its own correctness against the SPEC is
  the formal area's job (`reports/formal/`); here it is only the fault-free twin.
* `D_no_silent_loss` / `D_no_silent_beat_divergence` treat the internal `mismatch` as a stop in
  the upset-visible cycle, because `fault` only rises one cycle later by design.
* The campaign measures outcomes for one workload distribution and one seed (deterministic); the
  rates of the unprotected flip-flops (e.g. how often `out_valid_q` is 1 at the upset) depend on
  that workload. The formal part is exhaustive over inputs, lane, bit and cycle.
* `fault_q` can only flip 0 -> 1 in a single-upset campaign (it is 0 whenever the fault-free
  design runs), which gives a false fault stop (availability loss, no data error). Its 1 -> 0
  case (re-enabling a stopped design, SPEC section 8) needs two faults and is not measured.
* Nothing here is a radiation test; it checks the logic of the protection only.
